## Диагностика браузера: факты и гипотезы

В текущем наборе ALL_TOOLS нет callable browser/computer-use tools. Поэтому
пробовали shell → open / AppleScript, как ранее работавший путь.

Команды (Chrome; аналогично Brave):

```sh
open -a '/Applications/Google Chrome.app' --args --new-window https://www.reddit.com/r/sideprojects/submit
osascript -e 'using terms from application "/Applications/Google Chrome.app"' -e 'tell application "/Applications/Google Chrome.app" to get URL of active tab of front window' -e 'end using terms from'
```

Результаты:

- open и AppleScript повторно возвращали **-10827 / kLSNoExecutableErr**.
- Safari и System Settings: поиск по имени не находил приложения; открытие по
  полному пути тоже -10827. Проблема затрагивает несколько приложений.
- Проверены Info.plist/CFBundleExecutable всех четырёх приложений: исполняемые
  файлы существуют и имеют executable permission. file показывает Mach-O
  с ARM-архитектурами. Не считать браузеры удалёнными/повреждёнными.
- Прямой запуск Chrome binary завершился exit 134 с bootstrap_check_in
  Permission denied и доступом к Chrome/Crashpad/settings.dat Operation not permitted.
- /usr/bin/log show отказал: **Cannot run while sandboxed**.
- launchctl print gui/501 показал существующий GUI domain/session Aqua;
  полное отсутствие GUI-сессии не доказано. Не сохранять/публиковать полный dump.
- Пользователь проверил в своём обычном Terminal **open -a "Google Chrome"**:
  сообщил, что команда работает. Это локализует отказ к исполнению из среды агента.
- Повторные разрешения пользователя в тексте не изменили доступ среды.

Вывод: наиболее вероятен sandbox/контекст запуска среды агента, а не missing
executable. Точную заблокированную системную операцию и почему раньше работало
не установили. Не утверждать, что известно о смене разрешений или обновлении.

Apple: https://developer.apple.com/documentation/coreservices/3074489-anonymous/klsnoexecutableerr?language=objc
Официальное значение: executable missing or unusable format; локальные результаты
не подтверждают буквальное объяснение missing file.
OpenAI sandbox docs: https://learn.chatgpt.com/docs/sandboxing
В публичном openai/codex tracker найдены похожие reports #30043, #21292, #36696,
но они не подтверждают, что именно этот bug воспроизводится у нас.

Профиль этой сессии: workspace-write; sandbox_approval автоматически запрещён.
Не пытаться обходить sandbox, копировать cookies/профили или отключать защиту
браузера. Не запрашивали escalated execution и не получали auto-review rejection.
Переустановка браузеров/сброс LaunchServices/kill системных процессов не выполнялись.

## Следующие действия после перезапуска/восстановления подключения

1. Обнаружить реально доступные browser/computer tools. Если появился штатный
   browser tool — использовать его. Иначе один раз проверить AppleScript/open.
   Не повторять без изменений десятки одинаковых неудачных попыток.
2. Проверить существующую Reddit-сессию/правильного автора (ранее u/Random1k17),
   live sidebar/rules, историю дубликатов и формы трёх сообществ.
3. Отправить три разные подготовленные публикации с допустимыми медиа/flair.
   Авторизацию повторно не спрашивать. При CAPTCHA/логине не обходить ограничения.
4. После каждого submit получить **actual permalink**, время, фактический текст,
   медиа/flair и статус автора. Отдельно проверить signed-out доступность.
   Owner-visible post не равен публично доступному. Не переотправлять удалённые
   посты вслепую. Unavailable metrics = null, не 0.
5. Дописать историю в analytics.md и отдельный ledger; не заменять старые значения.
   Подготовленный kit не считается опубликованным размещением.
6. Проверить Uneed free submission при доступе, если продолжается запрос пользователя;
   различать saved draft, queued entry и опубликованную карточку.
