Версия исходников: 1.0.91. Это проверка локального кода с исправлениями,
не подтверждение качества опубликованной версии Google Play.

## Исправления и доказательства

1. **«Оставить на устройстве» удаляло ключ оставленных заметок.** Теперь ключ
   остаётся в SecureStore с привязкой к аккаунту. Гостевой режим восстанавливает
   этот ключ для чтения оставленных заметок; синхронизация остаётся выключенной.
   Тест проверяет заметку, AI-версию и корзину после очистки ключа в памяти
   и выполнения загрузки состояния `EncryptionProvider` в гостевом режиме.
2. **Параллельные первые сохранения создавали разные локальные ключи.** Теперь
   создание ключа использует один общий Promise. После сброса кеша все записи
   расшифровываются ключом из хранилища.
3. **Ошибка SecureStore считалась отсутствующим/успешно записанным ключом.**
   Ошибки чтения и записи ключа теперь передаются вызывающему коду: нельзя
   незаметно заменить ключ или использовать ключ, который не сохранился.
4. **Удаление локальных данных сохраняло старый курсор синхронизации.** Выход
   сначала останавливает синхронизацию, затем сбрасывает курсор перед очисткой.
   Следующий вход должен запрашивать полную историю. Живой запрос сервера пока
   не проверен; в тесте проверяется сброс состояния при выходе.
5. **Очистка аккаунта удаляла данные других аккаунтов на устройстве.** Очистка
   теперь ограничена `user_id`; чужие заметки, версии и корзина остаются.
6. **Выключенная/заблокированная синхронизация скрывала предупреждение о потере
   данных.** Перед диалогом выхода выполняется отдельный подсчёт метаданных SQLite,
   включая local-only, изменения версий и неотправленное аудио. Расшифровка для
   подсчёта не нужна. Одна заметка с несколькими изменениями считается один раз.
7. **Форма восстановления:** проверяет и нормализует код перед разблокировкой,
   блокирует повторную отправку и закрытие во время операции, очищает поля после
   закрытия и показывает локализованное сообщение для неверного кода. Отметка
   «ключ сохранён» записывается после проверки ключа, перед готовностью хранилища.
   Эти изменения проверены TypeScript; визуальный и интерактивный прогон ещё нужен.

## Выполненные проверки

`npm test` завершился успешно: TypeScript и все подключённые наборы тестов.
`git diff --check` — без ошибок.

Новый набор `npm run test:encryption-lifecycle` содержит **8 успешных проверок**:

- параллельное первое сохранение и холодный перезапуск модуля шифрования;
- повторная попытка после ошибки сохранения локального ключа;
- выход с сохранением заметок, версий, корзины и локального доступа;
- выход с удалением данных, удалением ключа и сбросом курсора;
- ошибки нативного хранилища при чтении/записи ключа;
- изоляция очистки заметок, версий и корзины другого аккаунта;
- предупреждение о данных без серверной копии при недоступном ключе;
- восстановление текста и аудио из шифротекста по коду восстановления после
  очистки локального хранилища ключей; неверный ключ не расшифровывает данные,
  а заблокированный E2EE не отправляет текст открытым.

В тестах используются настоящий SQLite (`node:sqlite`) и криптография приложения.
Границы Android SecureStore, Expo SQLite, авторизации и синхронизации подменены;
React hooks выполняются в ограниченном тестовом адаптере, без настоящего React
renderer. Этот набор требует Node с `node:sqlite`; прогон выполнен на Node 24.21.0.
Он не заменяет Android, React UI и проверку сервера.

Четыре проверки повторно запущены против исходников `HEAD` до наших изменений:
все четыре ожидаемо упали — параллельное шифрование (`invalid ghash tag`),
сохранение ключа при выходе, сброс курсора и передача ошибок SecureStore.
На исправленных исходниках эти проверки проходят.

Локальные журналы текущего прогона:

- `/private/tmp/vaulto-note-encryption-tests-2026-10-18.log` — полный `npm test`;
- `/private/tmp/vaulto-note-encryption-lifecycle-2026-10-18.log` — итоговые 8 проверок;
- `/private/tmp/vaulto-note-encryption-baseline-2026-10-18.log` — 4 воспроизведения

## Обязательный следующий прогон на Android

Использовать отдельный тестовый аккаунт и вымышленные заметки. Сначала проверить,
что в выбранном AVD нет пользовательских данных. Удаление приложения — только
после подтверждённой синхронизации тестовых заметок и сохранения recovery key.

| Сценарий | Что проверить | Статус |
| --- | --- | --- |
| Первый вход и автоматическое E2EE | Понятный статус, сохранение recovery key, отсутствие повторных окон | Не выполнен |
| Создание и изменение | Русский текст, emoji, чеклист, AI-версии, аудио, отсутствие потерь после перезапуска | Не выполнен |
| Выход → «Оставить» | Заметки, версии и корзина доступны гостю и после холодного запуска; sync выключен | Не выполнен |
| Выход → «Удалить» → повторный вход | Полная загрузка даже при старом курсоре; прочие аккаунты не затронуты | Не выполнен |
| Выключенная sync / offline → выход | Предупреждение о новых, local-only заметках, версиях и аудио | Не выполнен |
| Удаление и переустановка APK | Повторный вход в тот же аккаунт и восстановление текста, версий, аудио | Не выполнен |
| Автоматическое восстановление ключа | Google Block Store доступен / недоступен / содержит старый ключ | Не выполнен |
| Ручное восстановление | Верный, неверный и чужой корректный код; вставка с пробелами/переносами; повторная попытка | Не выполнен |
| QR | Камера, отказ в разрешении, импорт сохранённого JPEG, отмена выбора | Не выполнен |
| Смена аккаунта | Ключ и содержимое аккаунта A не появляются в B | Не выполнен |
| Два устройства | Изменение заметки и версии, offline-правка, удаление, восстановление доступа | Не выполнен |
| Потеря сети и закрытие приложения | Вход, восстановление и sync возобновляются без дубликатов/пропавших заметок | Не выполнен |
| Интерфейс | RU/EN, светлая/тёмная тема, увеличенный шрифт, клавиатура, Back, быстрые повторные нажатия | Не выполнен |

Импорт QR сейчас явно принимает JPEG. Поддержка произвольных PNG-скриншотов
не добавлена и не проверена. Корзина локальная; её перенос через сервер после
переустановки не подтверждён и здесь не обещается.

Релиз, отправка в Google Play и изменения серверов не выполнялись.


## Этап 2 — доступы открыты, реальный Android-прогон 18 октября 2026

Среда: два отдельных чистых AVD Pixel 7, API 36, Google APIs, arm64
(`vaulto_recovery_qa_20261018` и `vaulto_recovery_qa2_20261018`). Установлен
нативный debug APK 1.0.91 с исправлениями будущего релиза 1.0.92, собранный
Gradle; JavaScript загружен через Expo dev client. Это не браузерная симуляция.
Существующий AVD с пользовательскими заметками не очищался.

Авторизация и синхронизация выполнялись через настоящие локально запущенные
сервисы проекта (FastAPI/PostgreSQL), без подмены HTTP ответов. Использованы два
вымышленных тестовых аккаунта; продакшен-база и реальные заметки не изменялись.
Сохранены машинные результаты и скриншоты в закрытой временной директории
`/private/tmp/vaulto-recovery-qa-20261018/`. Recovery key, QR с ключом и снимки БД
в репозиторий не включены.

Дополнительно по SQLite и PostgreSQL проверены зашифрованные заголовки/тексты
(`v3d` локально у гостя, `v3m` у E2EE-аккаунта), отсутствие открытого тестового
текста в серверных полях. Успешный вызов native Block Store в рамках той же
установки позволил восстановить доступ после выхода с удалением. На чистом
эмуляторе без Google cloud backup после удаления приложения потребовался
recovery key — этот путь проверен явно.

### Дополнительные исправления по результатам прогона

- Импорт PNG нормализует изображение нативным декодером в JPEG перед чтением QR;
  убран лишний шаг обрезки. JPEG также проверен.
- У нового устройства с заблокированными заметками показана инструкция
  восстановления вместо экрана первого запуска «здесь будут ваши заметки».
- Восстановление показывает ход операции. Введённый неверный ключ не отмечается
  как сохранённый и не вызывает окно первоначальной настройки.
- Исправлены формы числа в предупреждении о потерянных заметках RU/EN
  (дополнительно проверены значения 1, 2 и 5 через i18next).
- Комментарии о Block Store уточняют: постановка cloud backup в очередь ещё не
  подтверждает загрузку; перенос после переустановки зависит от Google Backup.

### Автоматические проверки и границы результата

Повторный `npm test` после всех изменений завершился с кодом 0, включая восемь
новых проверок жизненного цикла шифрования. Нативная сборка debug APK с модулем
обработки изображений прошла успешно. Журнал:
`/private/tmp/vaulto-recovery-qa-20261018/npm-test-final.log`.

Не проверены: Google OAuth на продакшене; восстановление ключа из Google cloud
backup между установками/телефонами; живая синхронизация аудио и AI-версий после
переустановки; все комбинации offline-конфликтов; живое распознавание QR камерой;
полный прогон всех экранов/языков/iOS. Криптографическое восстановление бинарного
аудио подтверждено автоматическим тестом, а не серверным Android-сценарием.
Корзина локальная и её серверное восстановление здесь не обещается.
Ввод ключа с изменённым регистром/переносами не получил отдельного итогового
UI-подтверждения; нормализация проверяется кодом/криптографическими тестами.

Результат подтверждает перечисленные сценарии; он не означает отсутствие всех
возможных багов. Подписанный production bundle проверяется отдельно при релизе.
